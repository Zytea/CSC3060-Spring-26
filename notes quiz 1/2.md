# Chapter 2: Data Representation

## 2.1 Information Storage

- **Byte**: A group of 8 bits. It is the smallest "addressable" unit of memory.
- **Address**: A unique numerical identifier that points to a specific location in the computer's memory.
- **Virtual address space (page)**: The set of all possible addresses.  
- **Physical address(frame):** bijectively mapped to virtual addresses in **页表（Page Table）** via the **Memory Management Unit (MMU)**.
  - **Pointer in C**: The virtual address of the first byte of some block of storage
  - **Type of a pointer**: Determines how the content in a block of bytes is interpreted.

#### Bits can Represent Any Information

- **Integer numbers** — Binary numbers, Signed/Unsigned numbers
- **Floating point numbers**
- **Memory locations (addresses)**
  - 32-bit machines: addresses are 32b, addressing up to 4GB
  - 64-bit machines: addresses are 64b, up to 16 ExaBytes (Kilo, Mega, Giga, Tera, Peta, Exa, Zetta, Yotta, …)
- **Computer Commands (Instructions)**

#### Integer Representation: Radix / Base

- A number system is an ordered set of symbols, called digits, with relations defined for addition, subtraction, multiplication and division.
- **Radix** or **base** of such is the total number of digits allowed.

### 2.1.2 Data Sizes and Pointer Sizes

- Modern computers have a **word size**, indicating ==the nominal size of pointer data==. Usually, the word size refers to the fixed-sized datum handled as a unit by the instruction set or the processor's hardware (i.e., the general-purpose register size ==一次性当作一个整体处理的数据大小==).

- **Current machines** (64-bit words): can address up to 2⁶⁴ bytes = **16 Exabytes**.

### 2.1.8 Logical Operations in C

C provides a set of logical operators `||`, `&&`, and `!`, which correspond to the **or**, **and**, and **not** operations of logic. The logical operations treat any nonzero argument as **true** and argument 0 as **false**.

- `!` is a logic operation; `~` is a bitwise NOT operation.
- `&&` and `||` are called **short-circuit operations**:
  - For `&&`, if the first argument is not true, the second argument does not need evaluation.
  - For `||`, if the first argument is true, the second argument does not need evaluation.
- In C, the expression `a && n/a` will not see div-by-0 errors.
- Expression `if (p && p->next)` will not encounter NULL reference.

#### ⚠️Common Bug

~~~c
if (A && B) -> if (A & B)
When `A = 2` (binary `10`) and `B = 1` (binary `01`):
- `A && B` is **true** (both are nonzero)
- `A & B` is **false** (bitwise AND of `10` and `01` is `00`)
~~~

## 2.2 Integer Representation

Two different ways bits can be used to encode integers:

- **Unsigned**: can only represent nonnegative numbers.
- **Signed**: can represent negative, zero, and positive numbers.

We also investigate the effect of expanding or shrinking an encoded integer to fit a representation with a different length (e.g., from a byte to a word or vice versa).

### 2.2.1 Unsigned Integer

For vector **x** 
$$
B2U_w(\vec{x}) \doteq \sum_{i=0}^{w-1} x_i \cdot 2^i \quad 
$$


## 2.2.2 Signed Integer

- **Signed Magnitude (True form)**: The most significant bit is the sign bit (0 for positive, 1 for negative); the remaining bits represent the magnitude.
  $$
  B2S_w(\vec{x}) \doteq (1 - 2x_{w-1}) \cdot \sum_{i=0}^{w-2} x_i \cdot 2^i \quad
  $$

- **1's Complement (Inverse form)**: Same as signed magnitude for positive numbers; for negative numbers, keep the sign and invert the rest.
  $$
  B2O_w(\vec{x}) \doteq (1 - 2x_{w-1}) \cdot \sum_{i=0}^{w-2} (1 - x_i) \cdot 2^i \quad
  $$

- **2's Complement**: Same as the true form for positive numbers; for negative numbers, keep the sign, invert the rest, and add 1.
  $$
  B2T_w(\vec{x}) \doteq -x_{w-1}2^{w-1} + \sum_{i=0}^{w-2} x_i \cdot 2^i \quad
  $$

|      | True (Signed Magnitude) | Inverse (1's Complement) | 2's Complement |
| :--: | :---------------------: | :----------------------: | :------------: |
|  +2  |        0000 0010        |        0000 0010         |   0000 0010    |
|  −2  |        1000 0010        |        1111 1101         |   1111 1110    |

#### Why Not 1's Complement?

1. **Two zeros**: `000000…000` (+0) and `111111…111` (−0)
2. **End carry-out issues**

#### Conversion

$$
U =
\begin{cases}
S + 2^w, & S < 0 \\
S,       & S \ge 0
\end{cases} \\ 
U = S \;mod\;2^w
$$

### 2.3.1 Addition and Subtraction 

- unsigned addition:
  $$
  x \;+\!^u_w\; y =
  \begin{cases}
  x + y, & x + y < 2^w \\
  x + y - 2^w, & 2^w \le x + y < 2^{w+1} \;(Overflow!)
  \end{cases}
  $$

- 

- unsigned inversion:
  $$
  -^u_w x = 
    \begin{cases}
    0, & x = 0 \\
    2^w - x, & 1 \le x < 2^w
    \end{cases}
  $$

- signed addition:
  $$
  x \;+\!^t_w\; y =
    \begin{cases}
    x + y - 2^w, & 2^{w-1} \le x + y < 2^w \;(Overflow!) \\
    x + y, & -2^{w-1} \le x + y < 2^{w-1} \\
    
    x + y + 2^w, & -2^w \le x + y < -2^{w-1} \;(Underflow!)
    \end{cases}
  $$

- signed inversion:
  $$
  -^t_w x = (∼x+1)\;mod\;2^w =
      \begin{cases}
      0, & x = 0 \\
      2^w - x, & 1 \le x \le 2^{w-1} - 1 \\
      -2^w - x, & -2^{w-1} \le x \le -1
      \end{cases}
  $$

## 2.4.4 FP Rounding

- **Rounding** is the task of getting the "closest" matching value x that can be represented in the floating-point format.
- IEEE offers **4 rounding modes:** ==Round-to-even, Round-towards 0, Round down, Round up==.
- The most commonly used (and default) mode is **round-to-even** (also called Round-to-nearest, Ties to even).
- ==如果 **正好在两个可表示数中点**，选 **最低有效位（LSB）为 0 的那个**==

| Value | Binary          | Situation                 | Result (Ties to Even) |
| ----- | --------------- | ------------------------- | --------------------- |
| 12.5  | $1.1001 × 2^3$  | Halfway between 12 and 13 | 12 (Even, 1100)       |
| 13.5  | $1101.1  × 2^3$ | Halfway between 13 and 14 | 14 (Even, 1110)       |

## 2.4.5 FP Operations

- Special rules: ==$\frac1{-0}$ yields **−∞**, while $\frac{1}{+0}$ yields **+∞**.==
- ==$\sqrt{-1}$ returns **NaN**.==
- FP operations are **commutative:** (a op b) == (b op a).
- FP operations are **NOT associative (**==(a+b)+c ≠ a+(b+c)==):**
  - `(3.14 + 1e10) - 1e10` evaluates to **0.0** (3.14 is lost due to rounding)
  - `3.14 + (1e10 - 1e10)` evaluates to **3.14**

**Impact on compiler/programmer:**

- Can (B+C) be treated as a CSE (Common Sub-Expression) in (A+B+C) vs (A+(B+C)) vs (B+A+C)? ❌ 
- Can (a+b+c+d) be converted to ((a+b) + (c+d))? ❌ 

## 2.4.5 FP Arithmetic

#### 2.4.5.1 FP/Int Type Casting

| Conversion            | Behavior                                                     |
| --------------------- | ------------------------------------------------------------ |
| int → float           | Cannot overflow, but may be **rounded**                      |
| int or float → double | Exact value **preserved** (double has greater range and precision) |
| double → float        | May **over/underflow** to ±∞; otherwise may be **rounded**   |
| float or double → int | Rounded **toward zero** (e.g., 1.999 → 1, −1.999 → −1); may overflow |

- C standards do not specify a fixed result for float-to-int overflow.

- Intel-compatible processors use bit pattern `[10…00]` (TMin) as an **integer indefinite value**.

- Example: `(int) +1e10` yields **−2147483648** (==截断==，negative from positive!).
  $$
  结果 = (int)(value\; modulo\; 2^{32})
  $$

#### 2.4.5.2 Floating-Point Addition

Compute: 1.000₂ × 2⁻¹ + (−1.110₂ × 2⁻²) = (0.5 + (−0.4375))

1. **Align binary points:** 1.000₂ × 2⁻¹ + (−0.111₂ × 2⁻¹)
2. **Add significands:** 1.000₂ × 2⁻¹ + (−0.111₂ × 2⁻¹) = 0.001₂ × 2⁻¹
3. **Normalize:** → 1.000₂ × 2⁻⁴ (no overflow/underflow)
4. **Round:** → **1.000₂ × 2⁻⁴** (no change) = **0.0625**

### 2.5.1 FP Adder / FADD

- FP adder usually takes **3-4 cycles** and can be **pipelined**.

### 2.5.2 FP Multiplier / FMUL

- Skips the first step of exponent alignment.
- Performs **partial products** and **adds two exponents** in parallel.
- Then: reduction → normalization → rounding.
- FP multiply usually takes **4–5 cycles** (one cycle longer than FADD).

### 2.5.3 FMA / FMAC Instructions (Fused Multiply and Add)

- Latency: **5–6 cycles**.
- The intermediate product is **not rounded** before addition — only **one rounding** at the end.

**Pipeline stages:**

1. Partial Product Generation
2. Partial Product Reduction
3. Final add (together with last step of reduction)
4. Normalization & Rounding

**FMA Benefits:**

- Higher throughput (two FLOPs per cycle)
- Lower latency
- Higher precision (one rounding instead of two)
- Smaller code size and greater energy efficiency

```bash
gcc -O3 -march=native -mfma -ffp-contract=fast
```
