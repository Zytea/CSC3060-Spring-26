## 4.2 Stack Allocation Before/During/After Procedure Call

**Before Call B():**

- Arguments 2, 1, and return address on stack
- `fp` and `sp` at the boundary

**During Call B():**

- Frame pointer (`fp`) points to old frame pointer location
- Local variables allocated between old `fp` and saved registers
- Saved registers stored below local variables
- Dynamic arrays at the bottom
- `sp` points to current stack top

**After Call B():**

- Stack returned to state before call
- Frame cleaned up

## 4.4 How is Procedure Call Supported in RISC-V

Stack accesses during procedure calls involve:

- Parameter passing
- Return address storage
- Save/Restore registers
- Return value handling

**Solution:** RISC-V relies on a software **calling convention** to efficiently use registers and reduce stack references.

**Calling Convention Definition:** An implementation scheme for how subroutines receive parameters, return results, set up for function calls, and clean up afterward.

**Key Points:**

- If code interoperates with external libraries, APIs, and middleware, adherence to calling convention is essential
- If code is self-sufficient, convention adherence is optional

## 4.5 Calling Convention Components

A calling convention involves:

- Parameters and return values/addresses
- Parameter passing mechanism
- Stack setup and cleanup
- Save/restore previous frame pointer
- Caller/Callee save register designation

## 4.6 RISC-V Register Convention

| RV Registers   | ABI registers | Purpose                          |
| -------------- | ------------- | -------------------------------- |
| X1             | ra            | Return address                   |
| X2 (sp)        | sp            | Stack top                        |
| X3             | gp            | Global pointer                   |
| X8 (fp)        | fp            | Frame pointer                    |
| X16-X18        | —             | Intra-procedure call scratch reg |
| X10-X17        | a0-a7         | **Arguments**                    |
| X5-X7, X28-X31 | t0-t6         | **Caller Save**                  |
| X8-X9, X18-X27 | s0-s11        | **Callee Save**                  |

## 4.7 Caller Save Registers

##### Definition:

These registers are expected to be preserved by the **caller** (the function making the call) if their values need to be retained across the function call. The **callee** can modify these registers without obligation to restore original values.

- **Caller Save Registers** 是由 **调用者**（即调用函数的代码）负责保存的寄存器。如果函数调用过程中这些寄存器的值需要保留，调用者需要在调用前保存它们的值，并在函数调用后恢复这些值。

- 被调用的函数（**Callee**）可以在执行过程中修改这些寄存器的值，但它没有责任恢复原始的值。

##### RISC-V Caller-Saved Registers:

- **t0-t6** (temporary registers) → X5-X7, X28-X31
- **a0-a7** (argument/return value registers) → X10-X17
- **ra** (return address register) → X1

```c
Function A() {
    $T1 = a*b;
    // Save $T1 before calling B()
    $S2 = B(1,2,3);  // B() is callee, A() is caller
    c = $T1 + $S2;
    // Restore $T1 after B() returns
    return;
}
```

A() must save `$T1` before calling B() and restore it when B() returns, because B() may modify caller-save registers.

## 4.8 Callee Save Registers

##### Definition:

The **callee** expects these registers to be preserved if modified during function execution. The **callee must save** original values upon entry (by pushing to stack) and **restore before returning** to caller.

- **Callee Save Registers** 是由 **被调用者**（即被调用函数）负责保存的寄存器。如果在函数执行过程中修改了这些寄存器的值，**被调用者** 必须在进入函数时保存这些寄存器的值（一般是通过将其压入栈中），并在返回时恢复它们，以便调用者能获取到原值。
- 被调用函数需要确保它不改变调用者的状态，除非该寄存器已保存并恢复

##### RISC-V Callee-Saved Registers:

- **s0-s11** (saved registers) → X8-X9, X18-X27
- **sp** (stack pointer) → X2

```c
Function A() {
    // Save $S1, $S2 at entry
    
    // A() uses callee-save registers $S1, $S2
    $S1 = a*b;
    $S2 = B(1,2,3);
    
    c = $S1 + $S2;
    
    // Restore $S1, $S2 before return
    return;
}
```

A() is responsible for saving/restoring `$S1` and `$S2` because other functions calling A() expect these registers to remain unchanged.

## 4.9 Ideal World vs Real World

### Ideal World:

- **Caller** uses all callee-save registers (X8-X9, X18-X27)
  - Caller does not need to save anything

- **Callee** uses all caller-save registers (X5-X7, X28-X31, X10-X17)
  - Callee does not need to save anything

### Real World:

Functions are often both **caller and callee**, creating the question: **"What registers to use?"**

## 4.10 Caller or Callee Save Registers? Cost Analysis

### Using Caller-Save (T1):

~~~c
Function A():
    $T1 = a*b;
    ... = B(1,2,3);  // Save before call
    ... = C(4,a);    // Save before call
    ... = D(x,y);    // Save before call
    ... = $T1;
// Total Cost: 6 save/restore operations (3 saves, 3 restores)

### Using Callee-Save ($S1):
Function A():
    $S1 = a*b;
    ... = B(1,2,3);
    ... = C(4,a);
    ... = D(x,y);
    ... = $S1;
~~~

- **Total Cost:** 2 operations (1 save at entry, 1 restore at exit)

**Conclusion:** Callee-save registers are more efficient when values persist across multiple function calls.

```asm
Function A:
    # 计算 a * b，并将结果存储在 $T1
    mul     $T1, $a0, $a1        # $T1 = a * b

    # 保存 $T1 的值
    addi    $sp, $sp, -4          # 为 $T1 分配栈空间
    sw      $T1, 0($sp)           # 将 $T1 保存到栈中

    jal     B                      # 调用 B(1, 2, 3)
    jal     C                      # 调用 C(4, a)
    jal     D                      # 调用 D(x, y)

    # 恢复 $T1 的值
    lw      $T1, 0($sp)            # 从栈中恢复 $T1
    addi    $sp, $sp, 4            # 恢复栈指针

    # 使用 $T1
    add     $v0, $T1, $T1         # $v0 = $T1 + $T1
    ret                            # 返回

# 使用 callee-save
Function A:
    # 计算 a * b，并将结果存储在 $S1
    mul     $S1, $a0, $a1        # $S1 = a * b

    # 调用函数 B
    jal     B                      # 调用 B(1, 2, 3)
    # 调用函数 C
    jal     C                      # 调用 C(4, a)
    # 调用函数 D
    jal     D                      # 调用 D(x, y)
    # 使用 $S1
    add     $v0, $S1, $S1         # $v0 = $S1 + $S1

    ret                            # 返回
```

## 4.11 General Rules for Register Allocation

### Rule 1: Caller Registers for Temporaries

**Why?** Temporaries are short-lived (used briefly, then discarded)

### Rule 2: Callee Registers for Local Variables

**Why?** Local variables tend to live longer (potentially as long as the entire procedure invocation)

### Rule 3: Callee Registers for CSEs (Common Sub-Expressions)

**Why?** CSEs are also long-lived within procedure invocation

## Practical Examples

### Example 1: Simple Test

```assembly
Function A():
    lw $8, -4($fp)
    lw $9, -8($fp)
    add $10, $8, $9
    sw $10, -12($fp)
    
    $v0 = B(1,2,3);  // Function call
    add $v0, $v0, $v0
    return
```

**Question:** What registers must be saved/restored across the call to B?
 **Answer:** **None** – no values live across function call B

### Example 2: Leaf Routine

**Definition:** A leaf routine calls no other functions

**Question:** What registers should be used?
 **Answer:** Use caller-save registers as much as possible – **no need to save/restore any registers**

### Example 3: Non-Leaf with Infrequent Calls

```c
Function A():
    // Calls B(), C(), D() only in ELSE part (rarely true)
    if (condition) {
        // Main path: no function calls
    } else {
        B(1,2,3);
        C(4,a);
        D(x,y);
    }
```

**Answer:** Use caller-save registers because save/restore occur in infrequent paths

## Summary

**Core Principle:** Ensure functions can interoperate efficiently and correctly

**Stack Management:**

- Local variables stored on stack
- Register values saved/restored as needed

**Register Usage:**

- **Argument passing:** a0-a7 (X10-X17)
- **Return values:** a0 and a1
- **Return address:** ra (X1)
- **Temporary registers:** t0-t6 (X5-X7, X28-X31) = **caller-saved registers**
- **Saved registers:** s0-s11 (X8-X9, X18-X27) = **callee-saved registers**

**Optimization Strategy:**

- **Leaf routines:** Use argument registers and caller-saved registers exclusively
- **Non-leaf routines:** Use callee-saved registers for values that persist across calls
- **Short-lived temporaries:** Allocate to caller-save registers
- **Long-lived values:** Allocate to callee-save registers to minimize save/restore overhead.
